# Python конвенции

## Правила

1. **Типизация**: все функции с type hints, возвращаемый тип обязателен
2. **Импорты**: `from package.module import Class`, не `from package import *`
3. **Docstrings**: только для public API, одно предложение
4. **Название файлов**: `snake_case.py`
5. **Название модулей**: по предметной сущности/понятию, а не действию или роли исполнителя. Избегать суффиксов `-er`, `-or` и мусорных имён `utils`, `helpers`, `common`, `manager`, `processor`, если это не термин домена
6. **Публичные имена**: отражают использование и доменный смысл, а не внутреннюю реализацию
7. **Классы и функции**: классы — существительные/понятия в `PascalCase`, функции и методы — действия в `snake_case`
8. **Доменный язык**: использовать термины предметной области вместо технических заглушек `entity`, `object`, `payload`, `record`, если есть точное слово
9. **Единый словарь**: один термин — одно значение. Не смешивать `get`, `fetch`, `load`, `retrieve`, если различие не закреплено в проекте
10. **Булевы имена**: как вопросы `is_*`, `has_*`, `can_*`, `should_*`, `requires_*`; избегать отрицаний вроде `is_not_*` и `no_*`
11. **Коллекции**: множественное число для коллекций (`users`), единственное для элемента (`user`)
12. **Типы в именах**: не кодировать тип без необходимости (`user_list`, `invoice_dict`, `str_name`); структура допустима, если она часть смысла (`price_by_region`)
13. **Ошибки**: называть по причине или нарушенному правилу; классы исключений заканчивать на `Error`
14. **Границы модулей**: имя модуля должно отвечать, что в него нельзя класть. Если нельзя ответить — граница слишком широкая
15. **Общие склады**: не создавать общие `api`, `types`, `interfaces`, `core`, `base` без узкой предметной причины
16. **Проверка места вызова**: имя считается удачным, если код читается естественно: `pricing.quote(order)`, а не `processor.process(order)`
17. **Абстракции**: небольшое дублирование лучше преждевременной общей абстракции с расплывчатым именем
18. **Сокращения**: только общепринятые (`id`, `url`, `http`, `api`), не самодельные
19. **Форматирование**: `ruff format`, линтер `ruff check`
20. **Не использовать**: `Any`, `Optional` без необходимости, bare `except`
21. **Пакетный менеджер**: только `uv` — `uv add <pkg>`, `uv sync`, `uv run <cmd>`. Не использовать `pip install`
22. **Конфиг ruff**: секция `[tool.ruff]` в `pyproject.toml`, не отдельный файл
