# Scope Classification

Ключевой вопрос: это локальный fix или нужна `plan-release`?

## Small-Fix подходит

| Признак | Да |
|---|---|
| Файлы | 1-3 файла |
| Поведение | точечная регрессия или ошибка |
| Архитектура | решение очевидно из существующего паттерна |
| Контракты | публичный API/schema/protocol не меняются |
| Проверка | можно проверить одной targeted проверкой или существующим test suite |
| Риск | низкий или средний, локальный |

## Направить в plan-release

| Признак | Причина |
|---|---|
| Новый публичный contract | требует явных acceptance criteria |
| Миграция/schema change | нужен план и rollback |
| Изменение протокола интеграции | высок риск совместимости |
| Больше 3 файлов | scope уже не маленький, кроме чисто механического rename/import |
| Несколько этапов | apply-small-fix не имеет stage tracking |
| Продуктовая неоднозначность | решение должен принять пользователь до ТЗ |

## Механическое исключение

Больше 3 файлов допустимо только если изменение однотипное и безопасное: rename импорта, форматирование одной строки, обновление одинакового ключа. В отчёте явно указать, почему это всё ещё apply-small-fix.
