# Module Size Review

Правило 500 строк — это gate перед merge, а не автоматический рефакторинг.

## Scan Scope

Проверять `.py` файлы в исходном пакете проекта, обычно `src/test_analysis/`.

Исключать:

- tests;
- generated files, если они явно помечены;
- vendored/external code;
- migration snapshots, если проект использует их как неизменяемые артефакты.

## PASS

Файл проходит, если:

- содержит не больше 500 строк; или
- в первых строках есть `MODULE_SIZE_REVIEWED` с датой и причиной.

## Если файл больше 500 строк

Предложить пользователю выбор:

| Вариант | Когда выбирать |
|---|---|
| Refactor | файл содержит несколько ответственностей, есть понятная граница разбиения |
| Keep reviewed | файл цельный, разбиение увеличит сложность или риск перед merge |

Если пользователь выбрал оставить, добавить в начало файла:

```python
# MODULE_SIZE_REVIEWED: {date}. Decision: keep. Reason: {one sentence}
```

## Не делать

- Не рефакторить большой модуль прямо внутри integrate-release без явного согласия.
- Не добавлять marker без причины.
- Не считать marker валидным, если он спрятан глубоко в файле.
