# Coverage Matrix

Матрица помогает не писать “много тестов”, а закрыть существенные риски реализации.

## Обязательные строки

Для каждого изменённого публичного contract проверить:

| Категория | Минимальный вопрос | Пример assertion |
|---|---|---|
| Happy path | Работает ли основной сценарий из spec? | результат/статус/артефакт совпадает с expected |
| Boundary | Что происходит на пустом, минимальном или максимальном входе? | пустой список, missing field, duplicate key |
| Error path | Ошибка превращается в поддержанный результат? | exception type, error object, status, log/diagnostic |
| Regression | Зафиксирован ли сценарий, ради которого меняли код? | воспроизведение прежнего сбоя |
| Runtime invariant | Не нарушен ли постоянный контракт системы? | порядок этапов, idempotency, no live call, no forbidden import |
| Artifact/state | Проверены ли созданные/изменённые артефакты? | file exists, markdown section, DB row, message payload |

## Рабочий шаблон

| Contract | Happy path | Boundary | Error path | Regression | Invariant/artifact | Test file |
|---|---|---|---|---|---|---|
| `{name}` | `{case}` | `{case or n/a}` | `{case or n/a}` | `{case or n/a}` | `{case}` | `{path}` |

## Достаточно

Покрытия достаточно, когда:

- каждый новый публичный contract имеет happy path;
- каждый риск medium/high имеет хотя бы один negative или boundary case;
- изменённые артефакты проверяются по содержанию, а не только по факту вызова;
- старые tests остаются GREEN;
- отсутствуют тесты, которые зависят от live network, текущей даты без clock stub или локальных абсолютных путей.

## Не требуется

Не добавлять тест, если он:

- повторяет assertion уже существующего теста без нового риска;
- тестирует внутреннюю реализацию вместо публичного эффекта;
- закрепляет случайный порядок, текст debug-сообщения или private helper без необходимости;
- требует real credential или внешнюю стабильность сервиса.
