# Lab Scan Reader

Прототип «ИИ читает сканы анализов и раскладывает показатели в карту пациента».

> Демо-прототип. Не медицинское изделие, не для диагностики. Только вымышленные данные.

- **Загрузка** — веб-UI, drag&drop скана (PDF/JPG/PNG), выбор демо-пациента, три готовых демо-скана.
- **Экстракция** — скан целиком уходит в vision-LLM через OpenRouter, ответ приходит по жёсткой JSON-схеме: `{test_name_raw, value, unit, ref_range, flag, confidence, needs_review}`. PDF растеризуется в PNG, отдельного OCR нет.
- **Нормализация** — справочник из 30–50 показателей ОАК и биохимии: синонимы сводятся к каноническому коду, единицы конвертируются, флаг «выше/ниже нормы» пересчитывается по справочнику.
- **Проверка человеком** — скан слева, редактируемая таблица справа. В карту записывается только после «Подтвердить».
- **Карта пациента** — таймлайн визитов и график тренда показателя с полосой референсного интервала.
- **Стек** — FastAPI (uv) + Next.js (статический export), SQLite, Docker Compose.

## Быстрый старт в Docker

```bash
docker compose up --build
```

Откройте <http://localhost:8000>. Без `.env` сервис стартует в режиме `fake`. Проверка:

```bash
curl localhost:8000/api/health
```

Ответ: `{"status":"ok","version":"…","extractor":"fake"}`.

Каталог `./data` монтируется в контейнер. В нём лежат справочник, seed, демо-сканы и фикстуры, туда же пишутся SQLite-база `data/patient_card.db` и загрузки `data/uploads/`. Пустая база при старте заполняется тремя демо-пациентами.

## Локальный запуск

Требуются Python 3.12 + [uv](https://docs.astral.sh/uv/) и Node 20.

```bash
uv sync
```

```bash
npm --prefix frontend ci
```

```bash
npm --prefix frontend run build
```

```bash
uv run uvicorn test_analysis.main:app --port 8000
```

Backend раздаёт собранный UI из `frontend/out` на <http://localhost:8000>. Для разработки фронта запустите `npm --prefix frontend run dev`: Next на :3000 проксирует `/api` на :8000.

Все пути (`data/…`, `frontend/out`) отсчитываются от рабочего каталога, поэтому запускать нужно из корня репозитория.

## Режимы экстракции

Настройки читаются из env или `.env`. Пример — [.env.example](.env.example).

| `EXTRACTOR` | Что происходит | Нужно |
|---|---|---|
| `fake` (по умолчанию) | Детерминированные ответы из `data/fixtures/extraction/{sha256}.json`, для незнакомого файла — `default.json`. Без сети и ключа. | — |
| `openrouter` | Реальная vision-модель через OpenRouter. | `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` |

Модель выбирается только через `OPENROUTER_MODEL` (например, `anthropic/claude-sonnet-4.5`), выбора в UI нет, смена требует рестарта. Модель должна поддерживать **vision** (изображения на входе) и **structured outputs** (`response_format: json_schema`), иначе экстракция падает с `502`. Если при `EXTRACTOR=openrouter` не задан ключ или модель, сервис не стартует.

В режиме `openrouter` сканы передаются третьей стороне — OpenRouter и провайдеру модели. Загружайте только демо-сканы из `data/samples/` или вымышленные данные.

Остальные параметры: `DATABASE_URL` (по умолчанию `sqlite:///data/patient_card.db`), `UPLOAD_DIR` (`data/uploads`), `MAX_UPLOAD_MB` (10), `MAX_PDF_PAGES` (5), `LLM_TIMEOUT_S` (120).

## Демо-сценарий

1. На `/` выберите пациента и загрузите скан, например `mixed_sidorova.png` из блока примеров.
2. На `/review` поправьте строки, подсвеченные жёлтым: выберите код для нераспознанной строки или снимите галочку «В карту». Затем нажмите «Подтвердить».
3. На `/patient` новый визит появится в таймлайне, а на графике тренда — новая точка.

## Данные и схема

Схема БД создаётся при старте через `create_all`, миграций нет. После изменения схемы удалите `data/patient_card.db`: при следующем старте он пересоздастся с демо-данными. Демо-сканы и фикстуры перегенерирует `uv run python scripts/generate_demo_scans.py`.
